# 오늘식단 서비스 기획서

## 1. 목적과 타겟

오늘 먹은 음식의 영양 정보를 복잡한 검색 없이 빠르게 확인하도록 돕습니다. 식단을 가볍게 기록하고 싶은 직장인, 대학생, 건강 관리 입문자를 대상으로 합니다.

## 2. 페이지와 이동

- 서비스 소개: 서비스 가치와 분석 시작 버튼을 보여줍니다.
- AI 분석: 음식 이름과 섭취량을 받아 결과를 출력합니다.
- 이용 안내: 입력부터 결과 확인까지 3단계 흐름과 참고 사항을 안내합니다.

상단 고정 메뉴의 앵커 링크로 각 섹션을 이동합니다.

## 3. AI 기능 설계

- 입력: 음식 이름(최대 100자), 섭취량(최대 50자)
- 처리: 프론트엔드가 `/api/analyze`로 요청하고, Python Serverless Function이 `GEMINI_API_KEY`로 Gemini API를 호출합니다.
- 출력: 칼로리, 탄수화물, 단백질, 지방, 나트륨, 실천 팁, 추정치의 한계
- 사용자 가치: 메뉴별 영양 정보를 빠르게 파악해 식단 선택에 참고할 수 있습니다.

## 4. 실패 처리 기준

- 빈 입력: 폼 아래에 필수 입력 안내를 표시하고 요청하지 않습니다.
- API 오류: 서버의 오류 메시지를 화면에 표시합니다.
- 지연: 프론트엔드가 20초 타임아웃 후 재시도 안내를 표시합니다.
- 주의: AI 결과는 의료 진단이나 치료 조언이 아닌 참고 정보입니다.

## 5. 검증 시나리오

1. `김치찌개`, `1인분`을 입력해 결과가 표시되는지 확인합니다.
2. 두 입력을 비운 채 제출해 안내 메시지를 확인합니다.
3. API 키가 없는 환경에서 서버 설정 오류가 사용자에게 표시되는지 확인합니다.
4. 390px 모바일과 1440px 데스크톱에서 메뉴, 폼, 결과가 겹치지 않는지 확인합니다.

## 6. 운영 및 제출 기준

- API 키는 GitHub에 저장하지 않고 Vercel 프로젝트 환경 변수로만 관리합니다.
- AI 결과는 참고용 추정치이며 의료 진단, 치료, 알레르기 판단을 대신하지 않습니다.
- 공개 배포 후에는 정상 결과, 빈 입력, API 오류, 지연 상황을 각각 확인하고 결과 화면을 캡처합니다.
- 프론트엔드는 `fetch('/api/analyze')`, 백엔드는 `api/analyze.py`의 Vercel Serverless Function으로 역할을 분리합니다.
- 제출 전 README의 배포 URL, GitHub 저장소, 증빙 체크리스트 상태를 실제 값으로 갱신합니다.
